# Benchmarks

## Methodology

See `docs/benches/METHODOLOGY.md` for full details. Summary:

### Test environment
- **Hardware**: AMD Ryzen 9 7950X / 64 GB DDR5-6000 / Samsung 990 Pro 2 TB (NVMe 4.0)
- **OS**: Ubuntu 24.04 LTS, kernel 6.8, Rust 1.82
- **Baseline**: `fio --name=seqread --rw=read --bs=1M --size=100G --direct=1 --ioengine=io_uring`

### Test images
| Image | Size | Filesystem | Files | Deletion type |
|-------|------|------------|-------|---------------|
| `fat32-bench.img` | 1 GB | FAT32 | 10,000 | Mixed |
| `exfat-bench.img` | 1 GB | exFAT | 10,000 | Mixed |
| `ntfs-bench.img` | 16 GB | NTFS | 100,000 | Mixed |
| `ext4-bench.img` | 16 GB | ext4 | 100,000 | Mixed |
| `carve-bench.img` | 64 GB | RAW | 5,000 carved | N/A |

### Metrics collected
- **Throughput** (MB/s) — bytes processed / wall time
- **Wall time** — total scan duration
- **Peak RSS** — `/usr/bin/time -v` maximum resident set size
- **CPU utilization** — average across cores
- **Results count** — candidates emitted
- **Recall / Precision** — against ground truth (fixtures only)

## Running benchmarks

```bash
# All benchmarks
cargo bench -p relift-bench

# Specific benchmark
cargo bench -p relift-bench bench_signature_sweep

# Save baseline
cargo bench -p relift-bench -- --save-baseline main

# Compare to baseline
cargo bench -p relift-bench -- --baseline main
```

Results saved to `target/criterion/` with HTML reports.

## Continuous benchmarking

- Weekly CI run on dedicated `c6i.4xlarge` instance
- Results published to `gh-pages` at `https://relift.rs/benchmarks/`
- Regression alert on >10% throughput drop
- Hardware specs locked in CI config

## Reproducibility

All benchmark images generated by `crates/relift-testkit` with fixed seeds. Same images = same results. Images committed to `fixtures/` for CI (small) and generated on-demand for large benchmarks.

To reproduce locally:
```bash
cd fixtures
make all  # Generates all fixture images
cd ..
cargo bench -p relift-bench
```
