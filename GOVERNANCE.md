# Project governance

This repository does not currently publish a formal maintainer roster, response-time commitment, or signed-release policy. GitHub repository settings determine who can merge changes and administer releases.

## Contributions and decisions

Use public issues and pull requests for proposals and code changes. Architectural decisions may be recorded in docs/decisions/. Reviewers should check implementation, safety, tests, documentation, and the stated support limits before merging.

## Security reports

Use the private disclosure instructions in SECURITY.md. Do not post exploitable vulnerability details in a public issue.

## Releases

A release is not considered stable or verified merely because a tag or draft exists. Release status, signatures, checksums, and platform validation must be stated from actual evidence. Current open release gates are tracked in docs/GAP_REPORT.md.
